# Recovery-only host candidate

This candidate runs the existing Django/allauth reset views, not another reset-token system. tools/recovery_host/wsgi.py exposes only reset paths, an explicit synthetic health marker and static assets. It does not import config.wsgi, migrate, seed an operator, start a publisher, run due tasks or expose business endpoints. Settings refuse non-synthetic databases and require the boundary marker. Mail is memory-only and external sockets are blocked except the synthetic database. Never replace the main app Dockerfile/start command with this package.

Dockerfile.recovery-staging builds existing CSS and collects static assets without connecting to a database or applying migrations. The Worker proxy uses a fixed reviewed backend origin and exact reset/static path allowlists. It strips Worker authorization/cookies, fixes forwarding headers, preserves native CSRF, prevents foreign redirects, bounds transport and disables caches. Missing config fails503. No RECOVERY_BACKEND_ORIGIN is installed in production by this source change.

Private QA uses a disposable PostgreSQL database at127.0.0.1:55440/revup_finish_synthetic only, with the boundary documented in tools/qa/14nov-recovery. Browser proof runs the existing allauth token reset through the actual Worker handler and confirms expiry/reuse rejection, old Worker-session revocation and password login. host-smoke.mjs and proxy-smoke.mjs start a migration-free Gunicorn process and verify styled forms, CSS, native CSRF and denied business/admin/scheduler routes. They require Python3.12 repository dependencies and QA-only Playwright/Chrome. REVUP_QA_PYTHON names that Python. Real mail, production recovery and hosted reliability remain unproved until separately verified.

The existing Render legacy instance is a free candidate, not a reliability guarantee: free instances can cold-start for about one minute, sleep after15idle minutes and suspend at monthly limits. Its existing auto-migrating startup must never run with a shared database. Keep old service configuration and secrets in a private rollback record, never in Git. Hosted synthetic proof precedes any production routing or database configuration. Existing Yoco links/manual activation are unchanged.
